# Decisions

- [services] Python 3.14 is what is installed locally; code stays 3.11-compatible (no 3.12+ only syntax).
- [services] UI (M6/M7) deferred per phase change; Makefile has `test-js` instead of `test-frontend`, and `demo-cli` (headless) instead of a UI `demo`; no `test-e2e` yet.
- [services] Service-side test fixtures live in `contracts/examples/` (data/fixtures is intel's folder).
- [services] Single root `requirements.txt` for the whole backend (includes pandas/scikit-learn/joblib for intel).
- [services] Makefile uses `PY ?= python` so it works on Windows Git Bash and elsewhere (`make PY=python3`).
- [services] API imports intel functions only via `backend/api/intel.py`, which switches between stand-ins and real modules with `USE_STANDINS`.
- [services] Added GET /weather/today (morning briefing needs heat/rain) and POST /reset (fresh demo state) beyond the PLAN.md endpoint list.
- [services] Scenario contract is `{name, task_id, windows}` so the debrief knows which task the replay belongs to.
- [services] Debrief overrun vs CAT estimate = uncontrollable_min + controllable_min ("9 minutes over" = 6 + 3).
- [services] Logging an incident auto-writes a `memory_incident` MemoryNote for the machine (48 h TTL).
- [services] Voice queue: a safety line cancels a playing coaching/info line (dropped) or care line (replayed after); the budget is used up when a coaching line is accepted, not when quiet mode drops it.
- [services] Speaker renders the event itself so it can switch to the English text when no Hindi voice exists (sets `fallbackToEnglish`).
- [services] Replay idle = machine_active false OR idling_time_min >= 10 in the window; idle lesson plays once per idle stretch once it reaches 10 min.
- [services] demo-cli drives the API in-process with FastAPI TestClient on a temp DB (no server to start); in-task lines come from the real JS replay via scripts/replay_cli.mjs.
- [services] Makefile sets APPDATA via cygpath when MSYS make drops it (otherwise pip --user packages are invisible).
- [services] Contracts aligned to what intel built (PLAN.md left these open): weather is a list `{hour, temperature_c, rain, wind_kmh}`; `scenario()` returns a window list and the API wraps it as `{name, task_id, windows}` with task_id = first task of today's plan; message keys are dotted (`warn.*`, `finding.*`); break reason `regular|heat`; telemetry timestamps in CSV style.
- [services] `contracts/examples/demo_scenario.json` is exported from the real API by `make export-scenario`; the JS integration test replays it through replay -> rules -> queue.
- [services] Offline voice: `make audio` (edge-tts, dev-only dependency in requirements-dev.txt) pre-renders lines to frontend/public/audio/{lang}/{hash}.mp3 with voices hi-IN-MadhurNeural and en-IN-PrabhatNeural (male, to match the masculine Hindi forms in the templates, e.g. "बोलूँगा").
- [services] Lines covered: everything said by the headless demo (demo_cli's rendering), the in-task lines from replaying the real contracts/examples/demo_scenario.json, and every slot-free template (safety, belt, breaks, lessons, commands). Lines with other slot values (e.g. a different proximity distance) use speechSynthesis.
- [services] modes.js -> edge-tts prosody: rate (r-1)*100 %, pitch (p-1)*100 Hz, volume (v-1)*100 % (alert = +15% / +30Hz / +0%). Volume is baked into the MP3.
- [services] Filename = sha1(voice|prosody|text)[:16]; unchanged lines are not re-downloaded, stale MP3s are pruned. Manifest entries = {message_key, lang, mode, text, slots, file}; lookup is by exact (message_key, lang, rendered text), preferring the same mode. A Vitest test checks JS render() reproduces every manifest text, so Python/JS rendering cannot drift silently.
- [services] speaker.js order: MP3 for the requested language -> (no Hindi TTS voice) English MP3 -> speechSynthesis. A Hindi MP3 plays even without a Hindi TTS voice (no fallback flag). Load/play errors (incl. autoplay blocking) fall back to speechSynthesis; a cancelled clip never fires end or fallback. The manifest is injected (`manifest` option or `setManifest(await loadManifest())`), so the speak/cancel interface is unchanged.
- [services] Audio was generated with intel stand-ins for morning/debrief numbers; rerun `make audio` after intel merges so those lines match the real predictions (fixed + in-task lines are already real).
- [services] Phrasing variants: every non-safety template key has 3 phrasings (the original + 2 alternatives) in en + hi; en[i] and hi[i] say the same thing with the same slots, so the English fallback keeps the chosen phrasing. Safety keys (SAFETY_KEYS: belt_before_move, seatbelt_unfastened, proximity_alert, safety_alert, warn.*, memory_incident) keep exactly one fixed phrasing; tests enforce both rules.
- [services] Variant choice lives in the voice queue (`createQueue({ phraser })`): a line gets `variant` when accepted, unless the event already has one; repeat() replays the same words. `createPhraser({ seed: DEMO_SEED })` (mulberry32, seed 42) for demo mode, `createPhraser()` (Math.random) otherwise; a key never gets the same phrasing twice in a row. SaathiEvent gains an optional `variant` field.
- [services] demo_cli picks variants with a seeded Python PRNG (deterministic run to run, but not the same sequence as the browser); `make audio` pre-generates every phrasing of every demo/fixed line (196 clips, ~7.4 MB), so whichever variant the app picks has an MP3.
