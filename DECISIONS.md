# Decisions

- [services] Python 3.14 is what is installed locally; code stays 3.11-compatible (no 3.12+ only syntax).
- [services] UI (M6/M7) deferred per phase change; Makefile has `test-js` instead of `test-frontend`, and `demo-cli` (headless) instead of a UI `demo`; no `test-e2e` yet.
- [services] Service-side test fixtures live in `contracts/examples/` (data/fixtures is intel's folder).
- [services] Single root `requirements.txt` for the whole backend (includes pandas/scikit-learn/joblib for intel).
- [services] Makefile uses `PY ?= python` so it works on Windows Git Bash and elsewhere (`make PY=python3`).
- [services] API imports intel functions only via `backend/api/intel.py`, which switches between stand-ins and real modules with `USE_STANDINS`.
- [services] Added GET /weather/today (morning briefing needs heat/rain) and POST /reset (fresh demo state) beyond the PLAN.md endpoint list.
- [services] Scenario contract is `{name, task_id, windows}` so the debrief knows which task the replay belongs to.
- [services] Debrief overrun vs CAT estimate = uncontrollable_min + controllable_min ("9 minutes over" = 6 + 3).
- [services] Logging an incident auto-writes a `memory_incident` MemoryNote for the machine (48 h TTL).
- [services] Voice queue: a safety line cancels a playing coaching/info line (dropped) or care line (replayed after); the budget is used up when a coaching line is accepted, not when quiet mode drops it.
- [services] Speaker renders the event itself so it can switch to the English text when no Hindi voice exists (sets `fallbackToEnglish`).
- [services] Replay idle = machine_active false OR idling_time_min >= 10 in the window; idle lesson plays once per idle stretch once it reaches 10 min.
- [services] demo-cli drives the API in-process with FastAPI TestClient on a temp DB (no server to start); in-task lines come from the real JS replay via scripts/replay_cli.mjs.
- [services] Makefile sets APPDATA via cygpath when MSYS make drops it (otherwise pip --user packages are invisible).
- [services] Contracts aligned to what intel built (PLAN.md left these open): weather is a list `{hour, temperature_c, rain, wind_kmh}`; `scenario()` returns a window list and the API wraps it as `{name, task_id, windows}` with task_id = first task of today's plan; message keys are dotted (`warn.*`, `finding.*`); break reason `regular|heat`; telemetry timestamps in CSV style.
- [services] `contracts/examples/demo_scenario.json` is exported from the real API by `make export-scenario`; the JS integration test replays it through replay -> rules -> queue.
- [services] Offline voice: `make audio` (scripts/generate_audio.py, edge-tts in requirements-dev.txt) pre-renders MP3s to frontend/public/audio/{lang}/{sha1(voice|mode|text)[:16]}.mp3 plus manifest.json; the app itself still makes no network calls.
- [services] Lines rendered = every say() of the headless demo (demo_cli run with say() intercepted, so text is identical) + every slot-free template + shift_hello per machine and memory_incident/incident_logged per category, in en and hi (88 clips, ~3 MB, committed).
- [services] Voices: en-IN-PrabhatNeural and hi-IN-MadhurNeural (male, matching the masculine Hindi templates, e.g. "बोलूँगा").
- [services] modes.js -> edge-tts: rate (r-1)*100 %, volume (v-1)*100 %, pitch (p-1)*50 Hz (alert = +15%/+0%/+15Hz, care = -15%/-20%/-5Hz); a test keeps the Python copy of MODES equal to modes.js.
- [services] speaker.js looks up message_key + lang + exact rendered text (preferring the same mode); a hit plays the MP3 (even with no Hindi OS voice, so no fallback warning); a miss, a load error or an autoplay block falls back to speechSynthesis. Interface unchanged; the result gains `source: audio|speech|none` and the speaker a `ready` promise (manifest fetch in the browser).
- [services] `belt_before_move` fires only when the idle stretch before an unbelted resume was >= `BELT_MIN_IDLE_MIN` = 2 idle minutes (rules.js, tunable via `beltMinIdleMin`), so brief pauses do not wear out the alert; after a shorter pause an unbelted resume speaks the ordinary `seatbelt_unfastened` line instead of staying silent. Demo unchanged (fires at 09:15 after a 24-min stop).
- [intel] Fatigue vs harder work: tried adding a load-cycles trend (cycles / shift's earlier median) as a 5th IsolationForest feature — rejected: it still flagged costly-terrain shifts (11/28 vs 12/28 at >= 1.0 L/cycle; a forest flags whatever dimension is unusual) and worsened synthetic results (11/21 caught vs 12/21, mid-shift false alarms 4/1764 vs 1/1764). Forest features unchanged.
- [intel] Instead the cycle trend gates the forest: a sustained last-hour anomaly counts as fatigue_drift only if last-hour median load cycles <= 0.8 x the shift's earlier median (`THROUGHPUT_DROP`) or >= 2 unbelted/alert windows (`GATE_MIN_LAPSES`). Measured on the 84 synthetic shifts (`python -m backend.ml.eval_drift`): 12/21 drift shifts caught, 0/63 full-shift false positives, 1/1764 (0.06%) mid-shift false alarms (unchanged), demo fires only at 13:45, crafted drift fires, 0/56 harder-terrain shifts flagged (was 24/56 without the gate); threshold insensitive over 0.75-0.9.
